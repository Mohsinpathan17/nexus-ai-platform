## Implementation changes

- Requests now use schema-constrained planning/source JSON while keeping validation, size limits and cancellation. Planning instructions explicitly keep requirements inside the requested frontend scope.
- Source prompting distinguishes a complete TSX module from an HTML fragment.
- A compiler failure permits one bounded repair request using the actual compiler output and unchanged approved scope. At most two source/verification attempts occur under the existing job deadline.
- Per-attempt check names, actual exit codes, output and source hashes are stored. A provider failure during repair preserves the first measured compiler failure; errors are not promoted to successes.
- Added isolated two-phase smoke scripts. Plan approval requires an explicit flag after review. Completed runs cannot be presented as newly generated by rerunning the build phase.
- Added a targeted counter behavior checker which verifies the source SHA256 against the recorded successful build, reconstructs it in a network-disabled Docker container, and serves only its compiled static files to a fresh internal browser context. CSP/request interception prevent outside networking; no accounts, credentials or APIs are exposed in that server.
